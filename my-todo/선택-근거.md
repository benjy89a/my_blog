# 선택 근거: 나만의 투두리스트 (프레임워크 선택)

## 1. 내 조건

| 항목 | 내용 |
|---|---|
| 만들 서비스 | TickTick 같은 투두리스트 웹사이트 |
| 사용자 | 나 (개인 생산성 향상용) |
| 해결할 문제 | 기존 앱은 유료이고, 쓰지 않는 기능이 많아 복잡함 |
| 실행 환경 | 웹사이트 (브라우저) |
| 개발 경험 | Python은 익숙함 / JavaScript·HTML·CSS는 처음 배우는 단계 / 웹 프레임워크는 이름만 들어 봄 |
| 개발 방식 | AI(Claude)와 함께 개발 |
| 시간 | 오늘 안에 프론트엔드 완성 |

### 우선 기준 2개
1. **인력·자료**: 쓰는 사람과 자료가 많아서, 막혔을 때 검색이나 AI로 답을 찾기 쉬운가
2. **장기 유지보수**: 나중에 알림, 데이터 저장, 동기화 같은 기능을 붙이고 고치기 쉬운가

> 처음에는 "AI 생성 결과의 검토 부담"과 "학습 부담"을 우선 기준으로 고려했다. 하지만 실제로 중요하게 여긴 것은 범용성과 나중의 활용도였기 때문에, 위 두 기준으로 확정했다.

## 2. 후보 3개 비교

⭐ = 우선 기준 / ⚠️ = 확인 필요

| 기준 | React | Vue | Svelte |
|---|---|---|---|
| AI 생성 결과의 검토 부담 | 중간. AI가 가장 잘 생성하는 편이지만, JSX(HTML과 JS가 섞인 문법)는 초보가 읽기 어렵다. | 낮음. 템플릿이 일반 HTML과 비슷해 읽기 쉽다. 단, AI가 Vue 2와 Vue 3 방식을 섞을 수 있다. | 중간~높음. 코드는 짧지만 Svelte 4에서 5로 문법이 크게 바뀌어 AI가 옛 문법을 섞을 가능성이 크다. ⚠️ |
| 학습 부담 | 높음. JSX와 훅(`useState` 등) 개념을 먼저 익혀야 한다. | 낮음. HTML 파일 하나에 불러와서 설치 없이 시작할 수 있다. | 낮음~중간. 문법은 쉽지만 npm과 빌드 도구 설정이 필요하다. |
| 생태계 | 가장 큼 | 큼 | 작은 편 |
| ⭐ 인력·자료 | **가장 많음** (한국어 자료 많음) | 많음 | 적음. 한국어 자료는 더 적다. ⚠️ |
| ⭐ 장기 유지보수 | **좋음.** 백엔드 연동이나 기능 확장 사례가 많다. | 좋음 | 보통. 버전 변경 시 수정할 부분이 생길 수 있다. |
| 트레이드오프 | 자료와 확장성은 최고지만, 처음 배우기에는 무겁다. | 빠르게 시작할 수 있지만, 생태계는 React보다 작다. | 코드는 가장 짧지만, AI 결과를 믿기 어렵고 자료가 적다. |

### 확인이 필요한 정보 ⚠️
- 컴퓨터에 **Node.js(npm)**가 설치되어 있는지: **확인 완료** (Node.js v24.11.1, npm 11.6.2). React와 Vite를 쓸 수 있다.
- 배포 위치: **GitHub Pages로 결정**. React(Vite) 빌드 결과를 올리려면 `base` 경로 설정이 필요하다.
- Svelte의 한국어 자료 양과 AI 생성 품질은 직접 확인하지 않은 추정이다.

## 3. 채택·기각 이유

### ✅ 채택: React
- **내 조건과 연결한 이유**: React는 범용적이라 학습 곡선이 있어도 나중에 활용도가 높다.
- **인력·자료**: 세 후보 중 사용자와 자료가 가장 많다. 웹 초보인 내가 막혔을 때 검색이나 AI로 답을 찾기 가장 쉽다.
- **장기 유지보수**: 이번에 뺀 알림, 데이터 저장, 기기 간 동기화를 나중에 붙일 때 참고할 사례가 가장 많다.
- **감수하는 점**: 학습 부담과 AI 코드 검토 부담이 크다. 그래서 기능을 최소한으로 줄이고(할 일, 목록만), AI가 만든 코드를 한 단계씩 확인하며 진행한다.

### ❌ 기각: Vue
- 배우기는 쉽지만, React보다 쓰는 사람과 자료가 적다(인력·자료).
- 나중에 다른 프로젝트나 일에 활용할 범용성도 React가 더 높다.

### ❌ 기각: Svelte
- 세 후보 중 자료와 커뮤니티가 가장 적다(인력·자료).
- 최근 문법이 크게 바뀌어서, 나중에 고치거나 AI 도움을 받을 때 혼란이 생길 수 있다(장기 유지보수).
